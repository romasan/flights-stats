# Статистика рейсов аэропортов

Node.js-сервер и веб-приложение для сбора и визуализации статистики рейсов аэропортов. Сейчас поддерживаются два аэропорта — Пулково (LED) и Уфа (UFA), архитектура позволяет легко добавить другие.

## Структура проекта

| Путь | Назначение |
|------|------------|
| `server/index.js` | Точка входа: HTTP-сервер (статика + API), запуск планировщика |
| `server/api.js` | REST API (Express router) |
| `server/db.js` | Инициализация SQLite (better-sqlite3), схема таблиц |
| `server/store.js` | Слой доступа к данным (запись/чтение рейсов и лога загрузок) |
| `server/archive.js` | Сохранение/чтение сырых JSON-ответов API на диске (архив) |
| `server/fetcher.js` | Загрузка одного набора рейсов (arrival/departure) с API аэропорта |
| `server/scheduler.js` | Планировщик: ежедневный сбор данных с ретраями (без cron) |
| `server/units/led.js` | Конфигурация аэропорта Пулково (LED): URL API, парсинг рейсов |
| `server/units/ufa.js` | Конфигурация аэропорта Уфа (UFA): построение POST-запроса, парсинг HTML-карточек, своё расписание |
| `server/units/index.js` | Реестр аэропортов ("units") |
| `public/index.html` | Одностраничное веб-приложение для визуализации статистики |

| `data/flights.db` | SQLite база данных (создаётся автоматически, не в git) |
| `data/raw/<CODE>/<год>/*.json` | Архив сырых ответов API (создаётся автоматически, не в git) |

## Как это работает

### 1. Сбор данных (`server/scheduler.js` + `server/fetcher.js`)

Сервер сам планирует и выполняет сбор данных — отдельный cron не нужен. У каждого аэропорта (юнита в `server/units/*`) своё расписание и ретраи:

- **Пулково (LED)** — ежедневный сбор: в заданный час (по умолчанию 01:00 по времени сервера, `FETCH_HOUR`) запрашиваются данные за вчера. При ошибке — ретрай через 1 час (`FETCH_RETRY_DELAY_MS`), всего до 4 попыток (`FETCH_MAX_ATTEMPTS`, т.е. 1 попытка + 3 ретрая). Если данные за вчера уже успешно загружены — повторная загрузка не выполняется.
- **Уфа (UFA)** — интервальный сбор: каждый час (`intervalMs`, по умолчанию 1 ч) запрашиваются рейсы за текущий день (дата «сегодня» считается по времени Уфы, `Asia/Yekaterinburg`, UTC+5) и обновляются их статусы. Ретраев нет (`maxAttempts: 1`), т.к. опрос и так происходит каждый час. Новые рейсы добавляются, а уже виденные обновляются по статусу/времени без удаления (режим `merge`), чтобы к концу дня не «терять» уже вылетевшие/прилетевшие рейсы.

Общий порядок сбора для каждого юнита и обоих типов рейсов (`arrival`, `departure`):

1. При старте сервера для каждого юнита вычисляется время следующего запуска и выставляется `setTimeout`.
2. Если после всех попыток данные получить не удалось — в таблицу `fetch_log` записывается ошибка (аналог прежней записи в `fetch_flights.log`); эта информация возвращается фронтенду через API и показывается как предупреждение.
3. Успешный ответ API сохраняется:
   - сырой JSON — в архив на диске: `data/raw/<CODE>/<год>/<type>-<YYYYMMDD>.json` (для отладки/повторного разбора в будущем);
   - распарсенные поля рейсов — в таблицу `flights` в SQLite (только то, что нужно для отображения — дата, номер рейса, статус, план/факт времени, аэропорт).

Данные о конкретном аэропорте описываются модулем в `server/units/`: там заданы расписание/ретраи, способ построения HTTP-запроса и парсинг ответа к единому нормализованному виду. Простые юниты (LED) задают `urls` и `parseFlight(raw, type)` (GET, ответ — массив). Юниты с другим форматом запроса/ответа (UFA) реализуют `buildRequest(type, fileDate)` и `parseFlights(raw, type, fileDate)` (POST с телом form-urlencoded и конкретной датой, ответ — JSON с HTML-карточками рейсов). Чтобы **добавить новый аэропорт**, нужно создать аналогичный модуль и зарегистрировать его в `server/units/index.js`; на фронтенде он автоматически появится в выпадающем списке (список аэропортов сервер отдаёт через `/api/units`).

### 2. API

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/units` | Список аэропортов: `[{ code, name }]` |
| GET | `/api/units/:code/flights` | Все данные для отображения по аэропорту одним запросом: `{ unit, generatedAt, departures[], arrivals[], fetchErrors[] }` |

Формат одного рейса в `departures`/`arrivals`:

```json
{
  "fileDate": "20260719",
  "flightNumber": "FV 6587",
  "status": "Отправлен",
  "plan": "2026-07-19T00:10:00.000",
  "actual": "2026-07-19T00:12:00.000",
  "eventDate": "2026-07-19",
  "airportCode": "SCW",
  "airportName": "Сыктывкар"
}
```

`fetchErrors` — список дней, за которые не удалось получить данные после всех попыток: `[{ date: "YYYYMMDD", types: ["arrival", "departure"] }]`.

Ответ API отдаёт только то, что нужно для отображения (без лишних полей исходного API аэропорта) и сжимается (gzip через `compression`), что при пары месяцев данных даёт запрос в разы легче, чем скачивание всех исходных JSON-файлов.

### 3. Визуализация (`public/index.html`)

Одностраничное приложение на HTML/CSS/JS без сборки (рендеринг выполняется в рантайме в браузере). Использует библиотеки (подключаются через CDN jsDelivr):

- **Preact** — UI-фреймворк (реактивный рендеринг интерфейса);
- **htm** — JSX-подобный синтаксис через tagged templates (без компиляции);
- **Chart.js** — построение графиков;
- **chartjs-plugin-datalabels** — подписи значений на графиках;
- **chartjs-chart-matrix** — тепловые карты.

Интерфейс разбит на Preact-компоненты (`Header`, `UnitSelect`, `Loader`, `SummaryCards`, `LineChart`, `HeatmapChart`, `StatsTable`, `FlightsPopup`, `FetchErrors`, `Content`, `App`), а сами графики Chart.js обёрнуты в компоненты через хуки `useRef`/`useEffect`.

При загрузке страница:

1. **Получает список аэропортов** (`GET /api/units`) и показывает выпадающий список в шапке (сейчас — «Пулково (LED)» и «Уфа (UFA)»).
2. **Загружает все данные выбранного аэропорта** одним запросом (`GET /api/units/:code/flights`).
3. **Агрегирует данные**:
   - дата рейса берётся по фактическому времени (ATD для вылетов, ATA для прилётов), при отсутствии — по плановому (STD / STA) — это поле `eventDate`, уже вычислено на сервере;
   - каждый рейс относится к статусу: `Отправлен` / `Прибыл`, `Задержан`, `Отмена`, `Без статуса`;
   - рейсы со статусом «Отправлен»/«Прибыл», фактически отправленные/прибывшие с задержкой от выбранного порога, показываются как «Задержан» (порог выбирается в выпадающем списке: 0 минут, 15 минут, 30 минут, 1 час, 2 часа, сутки, «не важно» — по умолчанию 1 час; при «не важно» статус остаётся как в данных, без учёта задержки).
4. **Строит визуализации**:
   - **Сводные карточки** — количество дней, общее число вылетов/прилётов, а также суммарное количество отменённых и задержанных рейсов (с учётом выбранного порога задержки) с долей от общего числа в процентах;
   - **Линейные графики** — количество рейсов по статусам по дням;
   - **Тепловые карты** — вероятность отмены или задержки вылета/прилёта по дню недели и часу суток. Статус (отмена/задержка) выбирается выпадающим списком между блоками графиков: для обеих метрик используется плановое время (STD/STA), при его отсутствии — фактическое (ATD/ATA), а количество таких рейсов показывается в блоке предупреждений; дни без данных исключены;
   - **Таблицы** — количество рейсов по дням и статусам с итогами по строкам и столбцам. Заголовки столбцов кликабельны (сортировка по возрастанию/убыванию), клик по дате открывает попап со списком всех рейсов за выбранный день (номер рейса, направление, плановое и фактическое время, статус; если дата планового времени отличается от даты фактического, перед временем серым показывается дата; задержка считается по фактической разнице с учётом дат (рейс, прибывший раньше плана, не считается задержанным), до 60 минут показывается в минутах, а крупные — в формате «N д N ч N мин»; внутри попапа также доступна сортировка по столбцам). Попап закрывается по крестику, клику вне окна или клавише Esc.
5. **Показывает статус загрузки** в строке состояния и предупреждения о днях, когда данные не удалось загрузить (из `fetchErrors`).
6. **Загружается автоматически** при открытии страницы и при смене аэропорта в выпадающем списке.

## Запуск

### Установка зависимостей

```bash
npm install
```

### Миграция существующих данных (нужно один раз, если есть старые файлы)

Если в корне проекта лежат старые `arrival-YYYYMMDD.json` / `departure-YYYYMMDD.json` и `fetch_flights.log` (формат прежнего `fetch_flights.sh`), их можно один раз перенести в SQLite и архив:

```bash
npm run migrate
# либо с явными путями:
node scripts/migrate-legacy.js --src=/path/to/old/files --log=/path/to/fetch_flights.log
```

Скрипт сохраняет сырые ответы в `data/raw/LED/<год>/...`, распарсенные рейсы — в `data/flights.db`, а по ошибкам из лога восстанавливает записи в таблице `fetch_log` (для дней/типов, по которым нет успешно загруженного файла).

### Запуск сервера

Для локальной разработки:

```bash
npm run dev
```

Для запуска в фоне на сервере используется [pm2](https://pm2.io/) (устанавливается автоматически как devDependency при `npm install`):

```bash
npm start   # запустить под pm2 с именем процесса flights-stats и сохранить конфигурацию (pm2 save)
npm run stop   # остановить процесс flights-stats
npm run logs   # смотреть логи процесса flights-stats
```

Сервер поднимает HTTP на порту `3000` (можно изменить через переменную окружения `PORT`), раздаёт статику из `public/`, отвечает на `/api/*` и запускает встроенный планировщик ежедневного сбора данных (сбор не требует cron — работает, пока запущен процесс сервера).

Переменные окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт HTTP-сервера |
| `DATA_DIR` | `<project>/data` | Каталог для БД и архива сырых JSON |
| `DB_PATH` | `<DATA_DIR>/flights.db` | Путь к файлу SQLite |
| `FETCH_HOUR` | `1` | Час (0–23) ежедневного запуска сбора для daily-юнитов (LED); может переопределяться в конфиге юнита (`fetchHour`) |
| `FETCH_RETRY_DELAY_MS` | `3600000` (1 час) | Задержка между повторными попытками при ошибке (значение по умолчанию; может переопределяться в конфиге юнита — `retryDelayMs`) |
| `FETCH_MAX_ATTEMPTS` | `4` | Максимум попыток на один тип рейсов (1 + 3 ретрая; значение по умолчанию; может переопределяться в конфиге юнита — `maxAttempts`) |

Параметры расписания и ретраев задаются в конфиге юнита (`server/units/<code>.js`): `schedule` (`daily` | `interval`), `intervalMs`, `fetchHour`, `maxAttempts`, `retryDelayMs`, `dateMode` (`yesterday` | `today`), `timeZone`. Если они не заданы — используются глобальные значения из таблицы выше.

### Просмотр статистики

Откройте `http://localhost:3000/` (или адрес сервера) в браузере.
