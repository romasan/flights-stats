# Статистика рейсов аэропорта Пулково (LED)

Проект собирает и визуализирует статистику рейсов аэропорта Пулково (Санкт-Петербург).

## Структура проекта

| Файл | Назначение |
|------|------------|
| `fetch_flights.sh` | Bash-скрипт для загрузки данных о рейсах с API аэропорта Пулково |
| `flights-stats.html` | Одностраничное веб-приложение для визуализации статистики |
| `README.md` | Документация проекта |
| `CLAUDE.md` | Инструкции для Cline по поддержке документации |
| `CHANGELOG.md` | Журнал изменений проекта |

## Как это работает

### 1. Сбор данных (`fetch_flights.sh`)

Скрипт запускается периодически (например, по cron) и выполняет следующие шаги:

1. **Определяет вчерашнюю дату** — с учётом ОС (macOS / Linux), в формате `YYYYMMDD`.
2. **Обращается к API аэропорта Пулково**:
   - `https://pulkovoairport.ru/api/?type=arrival&when=-1` — прилёты за вчера;
   - `https://pulkovoairport.ru/api/?type=departure&when=-1` — вылеты за вчера.
3. **Сохраняет данные** в JSON-файлы с датой в имени:
   - `arrival-YYYYMMDD.json`;
   - `departure-YYYYMMDD.json`.
4. **Имитирует браузер** через User-Agent, чтобы обойти базовую защиту от ботов.
5. **Выводит результат** — сообщения об успехе или ошибке для каждого типа рейсов.

Выходные JSON-файлы загружаются на сервер (в примере — `https://w.nbauer.ru/flights/`), откуда их читает веб-приложение.

### 2. Визуализация (`flights-stats.html`)

Одностраничное приложение на HTML/CSS/JS без сборки (рендеринг выполняется в рантайме в браузере). Использует библиотеки (подключаются через CDN jsDelivr):

- **Preact** — UI-фреймворк (реактивный рендеринг интерфейса);
- **htm** — JSX-подобный синтаксис через tagged templates (без компиляции);
- **Chart.js** — построение графиков;
- **chartjs-plugin-datalabels** — подписи значений на графиках;
- **chartjs-chart-matrix** — тепловые карты.

Интерфейс разбит на Preact-компоненты (`Header`, `Loader`, `SummaryCards`, `LineChart`, `HeatmapChart`, `StatsTable`, `FetchErrors`, `Content`, `App`), а сами графики Chart.js обёрнуты в компоненты через хуки `useRef`/`useEffect`.

При загрузке страница:

1. **Получает список JSON-файлов** с сервера (парсит HTML-листинг директории, ищет файлы вида `arrival-YYYYMMDD.json` / `departure-YYYYMMDD.json`).
2. **Загружает все JSON-файлы** обоих типов параллельно. Неудачные загрузки не прерывают работу — они фиксируются и показываются в предупреждении.
3. **Загружает лог загрузки данных** (`fetch_flights.log`), чтобы определить дни, когда данные не были собраны, и исключить их из статистики отмен.
4. **Агрегирует данные**:
   - дата рейса берётся по фактическому времени (ATD для вылетов, ATA для прилётов), при отсутствии — по плановому (STD / STA);
   - каждый рейс относится к статусу: `Отправлен` / `Прибыл`, `Задержан`, `Отмена`, `Без статуса`.
5. **Строит визуализации**:
   - **Сводные карточки** — количество дней и общее число вылетов/прилётов;
   - **Линейные графики** — количество рейсов по статусам по дням;
   - **Тепловые карты** — вероятность отмены вылета/прилёта по дню недели и часу суток (на основе планового времени STD / STA; дни без данных исключены);
   - **Таблицы** — количество рейсов по дням и статусам с итогами по строкам и столбцам.
6. **Показывает статус загрузки** в строке состояния и предупреждения о днях, когда данные не удалось загрузить (из лога или при ошибках чтения JSON).
7. **Загружается автоматически** при открытии страницы — данные всегда актуальны на момент загрузки.

## Запуск

### Сбор данных

```bash
./fetch_flights.sh
```

Для регулярного сбора добавьте задание в cron:

```bash
0 1 * * * cd /path/to/project && ./fetch_flights.sh >> fetch_flights.log 2>&1
```

### Просмотр статистики

Откройте `flights-stats.html` в браузере или разместите файлы на веб-сервере вместе с JSON-файлами и логом.
